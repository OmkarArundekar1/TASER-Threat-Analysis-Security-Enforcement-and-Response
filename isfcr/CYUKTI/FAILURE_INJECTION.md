# CYUKTI Failure-Injection Testing

`backend/tests/test_failure_injection.py` (18 tests) covers every failure mode from the cross-cutting engineering audit. For each: no uncontrolled crash, no unsafe fallback, no accidental MISP publication, no destructive response, a useful status/error returned.

| Failure mode | Verified behavior | Test |
|---|---|---|
| Neo4j unavailable | `/api/incidents/<id>/overview` and `/api/campaigns` return a clean JSON 503, not an unhandled exception / HTML error page. | `test_neo4j_unavailable_returns_clean_503_not_a_crash`, `test_neo4j_unavailable_on_campaigns_route_returns_clean_503` |
| Wazuh unavailable | `AlertFileHandler.__init__` tolerates a missing alert file — offset defaults to 0, no exception (Wazuh itself can't be "mocked down" as a unit test; this verifies CYUKTI's own tolerance for its absence). | `test_missing_alert_file_does_not_crash_the_listener_at_import` |
| GNN artifact unavailable | `embed_campaign()` returns `None` for a nonexistent model path (never raises); `/api/gnn/status` reports `gnn_available: false` cleanly. | `test_gnn_unavailable_embed_campaign_returns_none_not_a_crash`, `test_gnn_unavailable_dashboard_route_reports_false_not_error` |
| XGBoost artifact unavailable | `/api/ml/predict/severity` returns a clean 503 with a real explanation, not a crash. | `test_xgboost_unavailable_returns_clean_503` |
| MISP unavailable | `CTIPublisher.health_check()` returns `False` on a real connection error (never raises); `MISPSync.should_publish()` never itself attempts an HTTP call that could fail — it only reads the already-computed `cti.publish` boolean. | `test_misp_unreachable_health_check_returns_false_not_a_crash`, `test_misp_unreachable_does_not_block_campaign_processing` |
| Shuffle unavailable | An execution against an unconfigured `ShuffleClient` is marked `FAILED` with a real, honest per-action error message ("Shuffle is not configured...") — never silently marked successful, never retried into a destructive fallback. | `test_shuffle_unavailable_marks_execution_failed_with_honest_reason` |
| Invalid Wazuh alert | `resolve_mitre({})` (completely empty) and `resolve_mitre({"data": {...}})` (missing `rule` key) both resolve to `UNKNOWN`, never raise. | `test_completely_empty_alert_resolves_to_unknown_not_a_crash`, `test_malformed_alert_missing_rule_key_resolves_to_unknown` |
| Missing MITRE | Same as "invalid alert" above — `UNKNOWN` is the correct, honest outcome. | (same tests) |
| Missing attacker | `ThreatQualificationEngine.qualify()` with `attacker_ip=None` fails only the `has_ioc` check (not a crash, not a false pass) — `may_publish_to_misp` correctly becomes `False`. | `test_missing_attacker_ip_fails_the_ioc_check_not_a_crash` |
| Missing victim | `campaign_selection._ip_similarity()` returns `None` (not a fabricated 0.0 or a crash) when either IP is absent. | `test_missing_victim_ip_returns_none_similarity_not_a_crash` |
| Duplicate alert | `DeduplicationEngine.is_duplicate()` correctly flags the second occurrence of the same fingerprint as a duplicate after `register_event()` records the first. | `test_duplicate_alert_is_recognized_on_second_call_not_reprocessed` |
| Malformed IOC | `extract_iocs({})` (no `data` field at all) returns `(None, None)`, not a crash; falls back to agent identity when only `victim` IP fields are absent. | `test_extract_iocs_with_no_data_field_does_not_crash`, `test_extract_iocs_falls_back_to_agent_identity_when_victim_ip_absent` |
| Empty evidence | `BestCampaignSelector.select([])` returns `selected=None`, `confidence="NONE"` — never crashes on an empty candidate list; `ResponsePlanGenerator.generate()` with no qualification/selection produces an honest degraded plan (`misp_status: NOT_APPLICABLE`). | `test_best_campaign_selector_with_no_candidates_returns_none_not_a_crash`, `test_response_plan_generation_with_no_qualification_or_selection_degrades_honestly` |

## What this does NOT claim

These are unit-level failure injections (mocked/constructed failure conditions), not chaos-engineering-style live fault injection against the actually-running Wazuh/Neo4j/MISP/Shuffle processes in this environment. Combined with the *live* verifications recorded elsewhere in this session (Neo4j genuinely going down mid-session and being restarted; MISP genuinely being unreachable with an empty credential earlier in this project's history), most of these failure paths have also been observed for real at least once, not only simulated. **Correction**: `SHUFFLE_WEBHOOK` is now genuinely configured with a real URL in this environment (confirmed this phase) — the "Shuffle unavailable" test above still exercises the real, correct unconfigured-client code path (via an explicitly-constructed `ShuffleClient(webhook_url="")`), but this environment itself is no longer in that state, and the configured webhook was not live-triggered this phase (see `ARCHITECTURE_VERIFICATION.md`).
